# Operit 识题精简版

复用 Operit 原版识屏执行模块的安卓独立应用（0.2.6-test），仅接入 DeepSeek 官方 API。本临时测试版内置三题答题页，配置后点击桌面图标开始识题，也可再转到后台识别其他应用，通过通知栏关闭识题。

识屏与点击来自原作者的 OperitAccessbility 服务；图片归一化、缩放与编码使用 Operit 的 ImagePoolManager，合并为一个 APK。具体来源和删改范围见 [UPSTREAM.md](UPSTREAM.md)。

## 当前功能

- 只需要填写一个 DeepSeek API Key，固定使用 `deepseek-flash`
- 任意应用均可识题，没有目标应用白名单
- 支持当前屏幕中完整可见的单选、多选和判断题
- 根据选项当前状态执行点击，避免把已选答案反复取消
- 手动切换题目后继续识别，不自动翻页、滑动、填写文字或提交
- 本临时调试版显示可拖动的状态悬浮窗：轻点立即重识别，长按查看历史；截图和点击期间会短暂隐藏
- 一个最低重要级别、无声音与振动的通知显示状态；点击通知本身或“关闭识题”均会停止
- 确认 API Key 和权限后，点击桌面图标即开始运行并进入内置测试页；开启权限本身不启动识题，点“转到后台”继续测试其他应用
- 页面变化后废弃旧回答；关闭后取消待处理任务与请求
- 识题过程中发生异常时自动重试，连续失败逐步延长间隔；每次重新读取屏幕，不重放旧答案

## 手机要求与首次使用

Android 11 / API 30 或以上，无需 Root、Shizuku 或电脑控制。

GitHub 的临时 Debug 构建尚未固定签名。已安装旧测试版且无法覆盖安装时，需要先卸载，再安装新版，并重新填写 Key、完成系统授权；卸载后的重新授权与普通退出再打开是两种情况。

1. 安装精简版 APK，打开“Operit 识题”。它与原版 Operit 的应用 ID 不同，可以共存。
2. 输入 DeepSeek API Key，点击“保存并进入测试页”。尚未授权时会在页面内显示提示。
3. 点击“允许通知”完成系统授权；点击“开启无障碍服务”并在系统设置中启用本应用。
4. 返回应用只更新权限状态；权限齐全后，点击“保存并进入测试页”，或回到桌面点击应用图标，开始识题并进入“临时答题测试”。保持屏幕亮起并解锁，等待自动选项，再手动核对、切换下一题。
5. 下拉通知栏，点击“关闭识题”。重新打开应用可再次开始。

Android 的无障碍授权、通知授权以及部分手机的后台管理提示属于系统界面，首次使用需要本人完成。通知是否显示状态栏图标也由手机系统和用户的通知设置决定。

### 重新打开时的无障碍状态

0.2.3-test 修正了“服务未连接就提示未授权”的启动判断：

- 系统未启用本应用：提示开启无障碍服务。
- 系统已启用、服务尚未连接：显示“无障碍已开启，正在等待系统连接服务…”，配置页停留期间每半秒重试。本次由桌面点击或开始按钮发起时，连接后才开始识题并进入测试页。
- 通知未允许：单独提示通知授权。

离开配置页或开始编辑 Key 时停止重试。应用只读取系统保存的服务列表，不写入系统授权，也不保存虚假的“已授权”标志。

0.2.4-test 将启动动作与权限状态分开：无障碍服务连接、从权限页返回、普通页面恢复及系统恢复旧配置页，都不会开始识题或跳到测试页。点击桌面图标可启动或恢复现有运行流程；手动开始后正常切换应用会继续识题，直到从通知栏关闭。系统加载无障碍服务本身仍由 Android 管理，不等于已开始识题。

0.2.6-test 针对 Redmi / HyperOS OS3.0.302.0.WPLCNXM 的清后台行为，将无障碍反馈声明从 `feedbackGeneric` 调整为 `feedbackGeneric|feedbackSpoken`。本机系统的动态保护名单对第三方无障碍服务检查 `(feedbackType & 7) != 0`；此前的通用反馈不满足条件。本次对照中，旧版被 `SwipeUpClean` 强制停止并移出无障碍启用列表，声明语音反馈的禅定空间则保留原服务进程。此次只调整反馈类型声明，不增加实际语音播报、权限或自启动逻辑；通知关闭仍停止识题。该声明用于本测试版的系统兼容性验证，不代表提供读屏或其他语音辅助功能，也不能保证永久保留授权。新版清理后的保护名单、服务和开关状态仍须真机复测。

若一直等待，请检查系统无障碍开关是否仍开启，以及应用是否被限制在后台运行。小米/Redmi 用户可尝试允许后台自启动、应用省电策略设为“无限制”、锁定后台应用，入口因系统版本而异，参考[小米后台运行说明](https://www.mi.com/uk/support/faq/details/KA-592820/)。这些设置不能保证解决系统关闭授权或服务异常的问题，仍需真机验证。

## 内置测试页

页面使用真实单选按钮和复选框，依次显示：

| 题型 | 题目 | 正确选项 |
|---|---|---|
| 单选 | 2 + 3 = ? | B（5） |
| 多选 | 以下哪些数是素数？ | A、B、D（2、3、5） |
| 判断 | 1 千米等于 1000 米 | A（正确） |

等待自动选中后，点“核对本题”查看结果；“重做本题”清空选择，“下一题”循环切换三题。测试页不会按标准答案自动填写，仍需真实截图、DeepSeek 回答与手势点击。

点“配置”修改 Key 或权限；点“转到后台”测试其他应用；通知栏关闭后，可在测试页点“开始识题”重新运行。页面状态、核对结果和题目更换会触发新的识别，因此应等待自动选择后再核对。

临时例外只允许已恢复且持有焦点的测试页被读取，设置页继续禁止识屏。测试完成后，按 [TEST-PLAN.md](TEST-PLAN.md) 移除此页面和少量入口，不改识题模块。

## 临时悬浮状态与历史

- **轻点悬浮窗**：取消旧任务，重新截图并请求当前题目；即使页面未变化，也重新识别。仍由一个执行线程串行工作。
- **拖动**：调整悬浮窗位置。
- **长按**：打开识题历史。返回题目页后再轻点重试；配置和历史页不会发送给模型。
- **关闭**：点击通知“关闭识题”，同时移除悬浮窗、取消接口请求和后续点击。

历史保留本次进程最近 30 轮，可复制文字、清空；不保存截图、Key 或接口请求头。每轮包含应用、题干、选项、模型答案、点击目标与坐标，以及实际执行过程：

| 状态 | 含义 |
|---|---|
| 无法读取屏幕 | 未获得截图，未请求模型；也可能正处于配置/历史页 |
| 请求模型 | 截图成功，正在等待 DeepSeek |
| 未识别到题目 | 模型未返回完整可作答的题目 |
| 识别成功 | 已记录模型返回的题干、选项和答案 |
| 页面/选项已变化 | 旧回答被废弃，未继续点击 |
| 手势已完成 | 系统回调已完成，仍需继续核对控件状态 |
| 已确认选中/取消 | 点击后读到目标原生可勾选控件的状态 |
| 未达到目标状态 | 原生控件状态仍与目标不同 |
| 未观察到变化 | 手势完成，但没有观察到选项变化 |
| 界面有变化，待核对 | 无可靠原生选中状态，只能确认页面状态或选项区域变化 |
| 等待自动重试 | 记录异常原因和下一次重试的等待时间 |
| 开始重试 | 丢弃旧回答，重新读取当前屏幕后识别 |
| 识题暂停 | 启动或其他未恢复的错误记录在本轮历史中 |

悬浮窗采用现有无障碍服务的窗口，不增加“显示在其他应用上层”的权限申请。截图和手势期间暂时隐藏，避免自身遮挡。配置页继续保护 Key；内置测试页仍保留。

### 自动重试

0.2.5-test 在每次识题异常后等待 3 秒重新识别；连续失败时依次等待 6、12、24 秒，之后每 30 秒重试，成功完成一轮后恢复正常间隔。网络/接口、返回解析及点击异常都会重新读取当前屏幕，不保留待执行的旧答案。通知显示等待重试状态，悬浮窗与历史保留具体原因。

轻点悬浮窗仍可立即重识别，取消当前等待。点击通知关闭、服务中断或通知权限不可用时停止，不会在等待结束后重新请求或点击。此机制用于已开始的识题任务，不会因开启无障碍而自动开始任务，也不会重新开启系统权限；缺少配置导致无法启动时仍需先完成配置。

## 数据与使用范围

运行时，当前屏幕的 JPEG 截图和可读取的界面文字由手机直接发送至 `https://api.deepseek.com/chat/completions`。API Key 使用 Android Keystore 加密保存。截图经 Operit 原版截图流程短暂写入应用私有缓存，处理后删除，不写入相册。图片池不启用磁盘持久化。

屏幕每轮间隔约三秒检查一次，模型请求和点击串行执行。相同界面会跳过重复请求。受保护的页面可能无法截图；模型定位和答题也可能出错，当前版本尚无真机成功率数据。

## 构建入口

使用 JDK 17 或 21、Android SDK Platform 36，并配置 `ANDROID_HOME` 或 `lite/local.properties` 中的 `sdk.dir`。无需下载原版的 native 模块、终端子模块或模型资源。

在仓库根目录执行：

```sh
./lite/gradlew -p lite :app:testDebugUnitTest :app:assembleDebug --no-daemon --max-workers=1
```

APK 路径：`lite/app/build/outputs/apk/debug/app-debug.apk`。
